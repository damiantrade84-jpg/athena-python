## 2. Core Signal Logic

### 2.1 Setup types

Engine D supports three setup types (`scalp_engine.py:_classify_setup`, line 2510):

1. **Mean Reversion** (`setup_type == "mean_reversion"`):
   - Market state = `balance`, price at `outside_va` (above VAH / below VAL) or `at_vah` / `at_val`
   - Direction: above VAH → SHORT; below VAL → LONG
   - Target: POC
   - Requires at least one confirmation: absorption OR CVD agrees OR VWAP lean agrees
   - CVD actively opposing direction is a hard veto (unless proxy + no hard veto config)

2. **Trend Continuation** (`setup_type == "trend_continuation"`):
   - Market state = `imbalance`, price at LVN (or other trend locations)
   - Direction from HTF bias, AAA completion, or VWAP lean
   - Target: POC or opposite VA
   - `STRICT_TREND_LOCATION_LVN_ONLY: true` restricts to `at_lvn` only when strict Fabio gate is on

3. **Trend Extension** (`setup_type == "trend_extension"`):
   - Market state = `imbalance`, price `outside_va`
   - Direction: above VAH → LONG; below VAL → SHORT
   - HTF bias must align (hard veto if against)
   - Target: VA width projection
   - Needs aggression confirmation

### 2.2 Direction inversion prevention

Direction is determined by:
- Mean reversion: price location relative to VA (`scalp_engine.py:2546, 2598`)
- Trend continuation: HTF bias, AAA direction, or VWAP lean (`scalp_engine.py:2674-2683`)
- Trend extension: `above_va` boolean + HTF bias alignment (`scalp_engine.py:2736-2743`)

There is **no explicit direction-flip guard** inside `run_scalp_scan` — the setup classification logic inherently determines direction from price location. The execution paths (`execution.py` and `athena.py`) both re-run the scan at execution time and match direction, which acts as an implicit flip guard.

### 2.3 Score formula

Engine D uses a **rule-based quality score (0–100)**, not a multiplicative factor score like Engine A.

`ai_quality_grade()` (`scalp_engine.py:3143`):
- Location: 0–25
- Absorption: 0–20
- CVD confirmation: 0–15
- AAA sequence: 0–15
- VWAP alignment: 0–5
- Session overlap: 0–10
- HTF bias alignment: 0–5
- Spread penalty: −5 to +5
- Volume divergence: −10 to +10
- Stop-run penalty: −20 to 0
- Time-of-day adjustment: −5 to +5

**Grade thresholds** (`scalp_engine.py:3330-3342`):
- A: ≥ 80
- B: ≥ 60
- C: ≥ 40
- D: < 40

Grade maps to size multiplier: A=1.0, B=0.5, C=0.25, D=0.0.

### 2.4 Config threshold verification

Every config threshold in the signal path is read via `CONFIG.get("SCALP_ENGINE", {})`:
- `SETUP_MEAN_REVERSION`, `SETUP_TREND`, `STRICT_FABIO_GATE_ENABLED`, `STRICT_TREND_LOCATION_LVN_ONLY`, `ALLOW_NEUTRAL_CVD_AT_VA_EXTREME` — all read in `_classify_setup()`
- `VP_ENABLED`, `VP_LOOKBACK_BARS`, `VP_BINS`, `VP_VALUE_AREA_PCT`, `VP_LVN_THRESHOLD`, `VP_SESSION_AWARE`, `VP_PROXIMITY_PCT`, `VP_PROXIMITY_ATR_K` — all read in `_build_volume_profile()` and `_locate_price_vs_vp()`
- `ABSORPTION_VOL_MULT`, `ABSORPTION_MAX_MOVE_ATR`, `ABSORPTION_SMA_PERIOD` — read in `_check_absorption()`
- `CVD_SMOOTH_PERIOD`, `CVD_MIN_SLOPE` — read in `_check_cvd()`
- `AAA_ENABLED`, `AAA_ACCUMULATION_LOOKBACK`, `AAA_CONTRACTION_THRESHOLD`, `AAA_BREAKOUT_VOL_MULT` — read in `_check_aaa_sequence()`

## 3. Volume Profile (POC / VAH / VAL)

### 3.1 Computation method

**Primary path:** `volume_profile.py:compute_fixed_range_volume_profile()` (line 275):
- Input: list of OHLCV candles (session or fixed lookback)
- Bins: configurable (default 64), uses `np.linspace` for price edges
- Volume allocation: each candle's volume is distributed across touched bins proportionally by overlap (`volume_profile.py:376-382`)
- Zero-volume candles fallback to range-proxy (`volume_profile.py:365-368`)
- VA construction: starts at POC (max volume bin), expands left/right by adjacent volume until target % reached
- LVN: bins below 30% of POC volume

**Crypto trade-bucket path:** `scalp_engine.py:_build_trade_bucket_volume_profile()` (line 1286):
- Queries `athena.microstructure.trade_bucket_store.query_session_buckets()` for Binance aggTrade price buckets
- Calls `volume_profile.py:compute_bucketed_volume_profile()` (line 19)
- Requires `min_buckets` (default 3) and `min_volume` (default 0.0)

**Internal fallback:** `scalp_engine.py:_build_volume_profile()` internal histogram (line 1173) — used only if `volume_profile` module import fails.

### 3.2 Lookback window

- **Live:** `VP_LOOKBACK_BARS: 50` (default), applied to M15 candles
- **Session-aware:** For forex/index/stock/commodity, if `VP_SESSION_AWARE: true`, prefers prior-session candles from `split_completed_sessions()` to avoid overnight dilution (`scalp_engine.py:3938-3953`)
- **Backtest:** `BT_VP_LOOKBACK_BARS` → `SCALP_VP_LOOKBACK_BARS` → `VP_LOOKBACK_BARS` fallback chain (`backtest_runner.py:5821`)

### 3.3 Volume source

| Asset class | Live volume source | Backtest volume source |
|-------------|-------------------|------------------------|
| Crypto | Binance aggTrade buckets (real) → candle volume fallback | Trade buckets with `require_fresh=False` → candle fallback |
| Forex | EODHD intraday overlay (if whitelisted) → MT5 tick_volume | EODHD overlay with `live=False` → MT5 tick_volume |
| Commodity | EODHD intraday overlay (if whitelisted) → MT5 tick_volume | Same as live |
| Index | EODHD intraday overlay (if whitelisted) → MT5 tick_volume | Same as live |
| Stock | EODHD intraday overlay (if whitelisted) → MT5 tick_volume | Same as live |

**EODHD volume is volume-only** — it replaces the `vol` field on existing candles without changing OHLC (`eodhd_volume_overlay.py:257-300`).

### 3.4 Forming-candle policy

- **Structure (M15 VP):** `USE_FORMING_FOR_STRUCTURE: false` — forming bar excluded (`mt5_fetch_scalp_candles(include_forming=False)` at `scalp_engine.py:3805`)
- **Trigger (M5/M1):** `USE_FORMING_FOR_TRIGGER: true` — forming bar included (`scalp_engine.py:3824, 3852`)
- **Bias (H1):** `USE_FORMING_FOR_BIAS: false` — forming bar excluded (`scalp_engine.py:3884`)

**Backtest:** Explicitly drops forming candle for crypto (`backtest_runner.py:5728-5729`) and uses `include_forming=False` for MT5 (`backtest_runner.py:5736`).

### 3.5 Future leakage assessment

- **CONFIRMED:** VP is built from closed bars only (structure bars exclude forming). No look-ahead.
- **CONFIRMED:** Backtest walk-forward uses `candles[:i+1]` for signal detection, enters at `candles[i+1]` open (`backtest_runner.py:5854-6026`). No future leakage.
- **CONFIRMED:** Crypto trade buckets use `query_session_buckets` with `require_fresh=True` in live, `require_fresh=False` in backtest — this is the only divergence, and it is explicitly documented as a BT parity feature.

## 4. VWAP / Liquidity / Order-Flow Proxy

### 4.1 VWAP computation

`_check_vwap_lean()` (`scalp_engine.py:2431`):
- Primary: `indicators.calc_vwap()` with `band_mult=0.5` (configurable)
- Fallback: internal VWAP using `(high+low+close)/3 * vol` cumulative average over all provided candles (`scalp_engine.py:2459-2471`)
- **No session reset logic.** The VWAP is computed over the entire provided candle window (`context_for_vwap = m15_context[-vp_lookback:]` in backtest, `candles_m15` in live).
- **This is a significant approximation** — true VWAP requires tick-by-tick volume-weighting or at least intrabar volume distribution. Using OHLCV candles with `typical_price * vol` is a coarse proxy.

### 4.2 Liquidity / order-flow proxy

| Proxy | Real or proxy? | Source | Validity |
|-------|---------------|--------|----------|
| Aggression (absorption) | Proxy for true absorption | OHLCV candle body vs ATR + volume spike | All asset classes; unreliable on single-bar MT5 tick volume |
| CVD (crypto) | **Real** trade-bucket delta | Binance aggTrade price buckets | Crypto only |
| CVD (non-crypto) | Proxy via candle body ratio | `(close-low)/(high-low)` buy ratio × tick_volume | Forex/commodity/index/stock — very noisy |
| AAA sequence | Proxy | Absorption + range contraction + breakout volume | All asset classes |

The code explicitly labels these as proxies where appropriate (`scalp_engine.py:_engine_d_data_fidelity()`, line 1795).

### 4.3 Data fidelity reporting

Every signal includes a `data_fidelity` dict (`scalp_engine.py:4068-4077`) that reports:
- `vp_fidelity`: `real_trade_bucket` | `vp_candle_volume_proxy` | `vp_range_proxy`
- `cvd_fidelity`: `real_trade_bucket` | `cvd_candle_volume_proxy`
- `absorption_fidelity`: similar
- `aggression_uses_real_order_flow`: bool

This is **report-only** and does not gate execution unless `REQUIRE_AGGTRADE_FOR_CRYPTO_STRICT` or `REQUIRE_REAL_VOLUME_FOR_STOCKS` is enabled.

## 6. Fee, Spread, Slippage, Execution Realism

### 6.1 Spread filter

`check_spread()` (`scalp_engine.py:1085`):
- Forex: spread converted to pips via `spread_raw * point / pip_size`
- Index/stock/commodity: raw MT5 points compared against `MAX_SPREAD_POINTS`
- Crypto: always passes (`return True, 0.0`)
- Per-symbol overrides via `MAX_SPREAD_POINTS_OVERRIDES`

**Backtest:** `spread_pips=0.0` is passed to `ai_quality_grade()` (`backtest_runner.py:5995`). The backtest does **not** model spread rejection. This is a parity gap.

### 6.2 Fee guard

Engine D fee guard (`scalp_engine.py:4178-4221`):
```python
if cfg.get("ENGINE_D_FEE_GUARD_ENABLED", True):
    risk_distance_abs = abs(levels["entry"] - levels["sl"])
    risk_distance_pct = risk_distance_abs / levels["entry"]
    estimated_fee_pct, estimated_slippage_pct = _scalp_cost_assumptions(cfg, asset_type)
    estimated_total_cost_pct = estimated_fee_pct + estimated_slippage_pct
    cost_as_R = estimated_total_cost_pct / risk_distance_pct
    max_cost_R = float(cfg.get("ENGINE_D_MAX_COST_R", 0.20))
    min_stop_pct = float(cfg.get("ENGINE_D_MIN_STOP_PCT", 0.0005))
```

Rejection conditions:
- `risk_distance_abs <= 0` → `fee_guard_zero_stop`
- `risk_distance_pct < min_stop_pct` → `fee_guard_micro_stop`
- `cost_as_R > max_cost_R` → `fee_guard_high_cost`

**Cost assumptions** (`scalp_engine.py:2837`):
```python
cost_defaults = {
    "crypto": (0.0006, 0.0002),    # 6bp fee, 2bp slippage
    "forex": (0.00005, 0.00005),   # 0.5bp fee, 0.5bp slippage
    "commodity": (0.00010, 0.00010),
    "stock": (0.00010, 0.00005),
    "index": (0.00010, 0.00010),
}
```

**Issue:** These are **hardcoded defaults** in Python. The `ESTIMATED_FEE_PCT_BY_ASSET` and `ESTIMATED_SLIPPAGE_PCT_BY_ASSET` config keys exist in YAML but the `_scalp_cost_assumptions()` function reads them correctly (`scalp_engine.py:2846-2849`).

**Backtest fee model** (`backtest_runner.py:6223-6233`):
```python
risk_pct = sl_distance / entry
estimated_fee_pct, estimated_slippage_pct = _scalp_cost_assumptions(cfg, asset_type)
fee_R = estimated_fee_pct / risk_pct
slippage_R = max(tick_slippage_R, asset_slippage_R)
net_R = gross_R - fee_R - slippage_R
```

This is consistent with live cost assumptions.

### 6.3 Slippage

- **Live:** Not explicitly modeled in the signal path. Execution price is the broker fill price from `run_managed_execution()`.
- **Backtest:** `BT_SLIPPAGE_TICKS: 3` applied to entry price (`backtest_runner.py:6032-6037`):
  - LONG: `entry = open + slippage`
  - SHORT: `entry = open - slippage`

### 6.4 min_move / min_RR / min_edge vs fees

- `MIN_RR: 1.2` (configurable, unified floor)
- `score_group_overrides` provide per-group min_rr (e.g., `forex_majors: 1.2`, `nat_gas: 1.6`)
- Fee guard ensures `cost_as_R <= 0.20` of risk distance
- For forex at 0.5bp fee + 0.5bp slippage = 1bp total, with min_stop_pct = 0.0005 (5bp), cost_as_R = 1bp/5bp = 0.20 — this is at the threshold. For tighter stops, the fee guard will reject.

**Issue:** Crypto at 6bp fee + 2bp slippage = 8bp total. With `min_stop_pct = 0.0005` (5bp), `cost_as_R = 8bp/5bp = 1.6 > 0.20` — **the fee guard will reject all crypto signals with default settings unless the stop is > 8bp/0.20 = 40bp (0.4%)**. For BTC at typical M15 ATR of ~0.5%, this may pass, but for low-volatility periods it will block.

## 7. RR / SL / TP / Exit Logic

### 7.1 SL formula

`calculate_scalp_levels()` (`scalp_engine.py:2905`):

| Setup | Direction | SL placement |
|-------|-----------|-------------|
| Mean reversion | LONG | `val - buffer` |
| Mean reversion | SHORT | `vah + buffer` |
| Trend extension | LONG | `vah - buffer` |
| Trend extension | SHORT | `val + buffer` |
| Trend continuation | LONG | `poc - buffer` (if poc < entry), else `entry - atr*1.5` |
| Trend continuation | SHORT | `poc + buffer` (if poc > entry), else `entry + atr*1.5` |

Buffer = max(asset-class minimum, `ATR_M15 * BUFFER_ATR_K` (default 0.25))

**Forex spread adjustment:** buffer += half-spread (`scalp_engine.py:2968-2970`)

**ATR override:** If `ATR_SL_ENABLED: true`, the wider of structural SL and ATR-based SL is used (`scalp_engine.py:3036-3058`).

### 7.2 TP formula

- **TP1:** `entry ± (sl_distance * TP1_R_MULT)` where `TP1_R_MULT: 1.0` (default). This is the mechanical "pay yourself first" target.
- **TP2:** structural target (POC, opposite VA, or VA width projection), only if > TP1 in favorable direction.

### 7.3 min_rr enforcement

- `_scalp_min_rr_for_group()` (`scalp_engine.py:2810`) reads per-group overrides, falls back to `MIN_RR`
- `calculate_scalp_levels()` sets `rr_below_min = True` if TP direction is invalid (`scalp_engine.py:3102-3108`)
- In `run_scalp_scan()`, signals with `rr_below_min` are surfaced as WATCHLIST (non-executable) with fail reason `"rr_below_min"` (`scalp_engine.py:4169-4174`)

### 7.4 Max holding time / timed exit

Engine D **bypasses** `timed_exit_monitor.py` entirely (`timed_exit_monitor.py:1145`):
```python
if engine in ("scalp", "engine d", "scalp_vp"):
    return
```

Live exits are managed by **broker TP1/SL** at ticket level. There is no trailing or breakeven monitor for Engine D positions.

### 7.5 Same-bar TP/SL ordering — CONFIRMED FIXED

Backtest (`backtest_runner.py:6098`):
```python
same_candle_policy = str(cfg.get("ENGINE_D_SAME_CANDLE_POLICY", "conservative_sl_first"))
```

If both SL and TP1 are hit on the same bar (`backtest_runner.py:6129-6130`):
```python
if hit_sl_now and hit_tp1_now and same_candle_policy == "conservative_sl_first":
    hit_tp1_now = False  # assume SL hit first
```

This is the **conservative SL-first** policy, which prevents the same-bar TP-before-SL bias that invalidated pre-v12 backtests.

### 7.6 Live exit path vs backtest

| Aspect | Live | Backtest |
|--------|------|----------|
| Entry | Broker market order at M1/M5 | Next M15 open + slippage |
| SL | Broker hard stop | Walk-forward bar low/high check |
| TP1 | Broker hard TP1 | Walk-forward bar high/low check |

## 8. Backtest Path

### 8.1 Location

`backtest_runner.py:backtest_pair_scalp()` (line 5645).

### 8.2 Signal uses only past data

**CONFIRMED.** Walk-forward loop (`backtest_runner.py:5846-6400`):
- Signal detection uses `m15_context = candles[:i+1]` (all bars up to and including current closed bar)
- Entry is at `candles[i+1]` open (next bar)
- VP is built from `m15_context[-vp_lookback:]` or prior session

### 8.3 Realistic fill simulation

- Entry: next bar open + slippage (`backtest_runner.py:6030-6037`)
- Slippage: `BT_SLIPPAGE_TICKS: 3` × point
- Fees: per-asset fee % converted to R units (`backtest_runner.py:6223-6233`)
- Spread: **NOT modeled** — no spread filter in backtest

### 8.4 VP/VWAP recomputed per bar

**CONFIRMED.** VP is rebuilt at every walk-forward step (`backtest_runner.py:5876-5900`). VWAP is recomputed from `context_for_vwap = m15_context[-vp_lookback:]` (`backtest_runner.py:5968`).

### 8.5 Backtest result schema

`backtest_pair_scalp()` returns a dict with:

## 11. Risk / Guardian / Auto-Trade Safety

### 11.1 Execution path

**Modular path (`execution.py:2115`):**
1. `_engine_d_execution_block_reason()` — fail-closed grade/D/non-executable check
2. Broker connection + positions fetch
3. Level rebase to live price
4. `risk_check()` — kill switch, stale signal, drawdown, max positions, correlation, duplicate pair, SL/TP validation, position sizing, portfolio heat
5. `_guardian_pre_trade()` — SL/TP geometry, required fields, freshness, drawdown
6. `run_managed_execution()` — broker order
7. Audit log write

**Monolith path (`athena.py:9254`):**
1. Fresh scan + direction match
2. `gate_result != "PASS"` check
3. Broker connection + positions fetch
4. `risk_check()` — same as modular
5. **MISSING:** `_guardian_pre_trade()` is **never called**
6. `run_managed_execution()`
7. Audit log write

**Finding:** The monolith path bypasses Guardian's pre-trade invariant checks. Since the monolith registers `@app.route("/api/scalp-execute")` first, it is the active endpoint. The modular path's inclusion of `_guardian_pre_trade()` is a dead code path for monolith deployments.

### 11.2 Kill switch coverage

`risk_check()` line 742: `if kill_switch: return RiskApproval(False, ..., "KILL_SWITCH_ACTIVE")`. **CONFIRMED** active for Engine D.

### 11.3 Max daily trades

`run_scalp_scan()` checks `MAX_DAILY_LOSSES` against session state (`scalp_engine.py:3594-3607`). **CONFIRMED** active at scan time.

### 11.4 Duplicate signal protection

`risk_check()` line 897-902: blocks if already holding a position on the same pair. **CONFIRMED** active.

### 11.5 Stale signal rejection

`risk_check()` line 849-853: rejects signals older than `SIGNAL_MAX_AGE_SEC` (default 300s). **CONFIRMED** active.

### 11.6 Position sizing

`risk_check()` → `_calc_volume()` (line 1012) computes raw lots from account balance × risk % / SL distance. Then scaled by:
- `score_factor` = `confluenceScore / maxScore` (Engine D sets maxScore=100, so this works)
- `sizing_override` from request (default 1.0, clamped 0.25–1.0)
- `dd_factor` from drawdown circuit breaker

**CONFIRMED:** Executors never size their own orders. `RiskApproval` carries the computed volume.

### 11.7 Leverage caps

`risk_engine.py` enforces `MAX_RISK_PER_TRADE` (default 3%) and `MAX_PORTFOLIO_HEAT` (default 6%). **CONFIRMED** active.

## Overall Assessment

### 1. Is Engine D functioning as designed, partially broken, or fundamentally flawed?

**Partially broken.** The core Fabio Valentini VP+order-flow methodology is implemented and largely sound. The three-pillar classification, grading, and level calculation are coherent. However:
- The **monolith execution path bypasses Guardian** (Critical, BUG-D-1)
- **8 config keys are missing from YAML** (High, BUG-D-4)
- **Auto-trader does not integrate Engine D** (Critical, BUG-D-2 — may be by design but undocumented)
- **Backtest uses M15 proxy only** with known divergence from live M1/M5 (High, BUG-D-3)
- **Fee guard is too strict for crypto** with default settings (Medium)

### 2. Can Engine D backtest results be trusted right now?

**Conditionally.** The backtest is mechanically correct (walk-forward, no future leakage, conservative SL-first same-bar policy). However:
- M15 proxy ≠ M1/M5 live execution
- No spread filter in backtest
- Session grading defaults to `"all"` while live uses `"london_ny"`
- Results should be treated as **directional evidence** for strategy viability, not as precise predictors of live P&L.

### 3. Can Engine D live signals be trusted right now?

**With reservations.** The signal generation is sound, but:
- The monolith execution bypasses Guardian geometry checks
- Grade D signals are still emitted to UI (noise)
- No auto-trader integration means signals require manual execution
- Crypto fee guard may over-reject during low-vol periods

**Recommendation:** Fix BUG-D-1 (Guardian bypass) before trusting live execution.

### 4. Is the Research Lab Engine D proxy close enough to production to guide changes?

**No.** The `engine_d_proxy` strategies in `athena_research/strategies.py` are simplified momentum/breakout algorithms with no VP, no order-flow, no session logic, and no grading. They share the "scalp" label but are mathematically unrelated to production Engine D. Research Lab results from these proxies **cannot** guide live Engine D tuning.

### 5. What is the single highest-priority fix before trusting Engine D?

**Fix BUG-D-1: Add `_guardian_pre_trade()` to the monolith `api_scalp_execute()` path in `athena.py`.** This is a one-line insertion before `run_managed_execution()`. Without it, invalid signals (inverted SL/TP, stale data, missing fields) can reach the broker.

### 6. What must be tested *after* that fix lands, and what would prove the fix worked?

**Tests to add:**
1. **Guardian rejection test:** Send a signal with inverted SL/TP to `/api/scalp-execute` and assert it returns 400 with Guardian reason, not 500 or broker error.
2. **Stale signal test:** Send a signal with timestamp > 10 minutes old and assert Guardian rejects it.
3. **Missing fields test:** Send a signal without `tp1` and assert Guardian rejects with `SIGNAL_MISSING_FIELDS`.
4. **Fee guard crypto test:** Verify that a crypto signal with M15 ATR producing stop < 0.0005 (5bp) is blocked by fee guard.

**Proof the fix worked:**
- All 4 tests pass on both modular (`execution.py`) and monolith (`athena.py`) paths.
- Audit logs show zero Engine D trades with `INVALID_LEVELS` or `STALE_SIGNAL` after the fix.
